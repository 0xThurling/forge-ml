# Conventions

Everything in the stack follows these rules. They exist so that any file can be
implemented (or replaced) without reading the rest of the codebase — and so
that the general infrastructure lives in ForgeFP exactly once.

## Language and build

| Item | Rule |
|---|---|
| Standard | C++20 |
| Namespace | `forgeml` for public API, `forgeml::detail` for internals |
| Layout | Header-only: every definition is `inline` or a template; only `main.cpp`, demos and tests are translation units |
| Build | Forge (`forge build`) or plain CMake; `.config/cmake/CMakeLists.txt` is generated by Forge |
| Dependencies | ForgeFP (local or git) + GoogleTest for tests (`testing = true` in `forge.lua`) |
| Flags | `-Wall -Wextra -Wpedantic`; add `-pthread` when using `fp::simd` / `fp::concurrent` |

Header-only is a deliberate choice: it keeps the build graph trivial and matches
ForgeFP. If a non-template function becomes large and hot, it may move to a
`.cpp` later, but the header keeps the declaration.

### `forge.lua` (target)

```lua
return {
  project = { name = "ml", type = "executable", standard = "20" },
  testing = true,
  dependencies = {
    direct = {
      forgefp = {
        git = "https://github.com/0xThurling/ForgeFP.git",
        tag = "main",
        target = "forgefp",
      },
      googletest = {
        git = "https://github.com/google/googletest.git",
        tag = "v1.14.0",
        target = "GTest::gtest_main",
      },
    },
    conan = {},
  },
  resources = { files = {} },
  scripts = {},
  features = {},
}
```

Include style: `<forgefp/fp/all.hpp>` (installed mirror) or `<fp/...>` when
building with `-I fp/src`. The domain headers include fp headers individually,
so the dependency of each file is visible.

## The division of labour (the first rule)

**If ForgeFP has it, ForgeML uses it. If ForgeML needs a general operation fp
lacks, the general part is added to fp and only the ML semantics stay here.**

| Belongs in ForgeFP | Belongs in ForgeML |
|---|---|
| containers' raw memory (`Buffer`), ownership (`Box`, `Shared`), arenas | dataset/model semantics |
| linear algebra (`matmul`, `solve`, norms, reductions) | losses, metrics |
| numerics (`softmax`, `sigmoid`, `linspace`, `central_difference`) | activations that are ML-specific (`gelu`, `leaky_relu`) |
| randomness (`fp::Rng`) | train/test splits, batching policy |
| time (`Stopwatch`) | epoch/step reporting |
| serialization encoding (`to_text`, `to_bytes`) | checkpoint schema (which tensor is which) |
| forward-mode autodiff (`Dual`) | reverse-mode layer graphs |
| iteration/parallelism (`inplace`, `views`, `par_for`) | training loops, optimizers |

The test for "general": *does the function mention a dataset, label, loss,
layer, epoch, or class?* If not, it can live in fp.

## Error model

Three kinds of failure, three mechanisms:

| Kind | Example | Mechanism |
|---|---|---|
| Expected, recoverable | shape mismatch, empty dataset, singular matrix, bad CSV row | `fp::Result<T>` (`fp::fail("...")`, `fp::ok(v)`) |
| Several problems at once | validating a matrix / dataset / hyperparameter grid | `fp::Validation<T>` then `fp::to_result` |
| Programmer error (bug) | index out of range, invariant broken | `ML_ASSERT(cond, "msg")` -> throws `MlError` |

Rules:

- Constructors may assert; they never return `Result`. Fallible construction
  goes through a named factory: `make_matrix(...) -> fp::Result<Matrix>`.
- Public functions that can fail with bad *input* return `Result`, even when the
  caller is internal. `Result` propagates with `>>=` / `fp::and_then`.
- Never `throw` for input validation, never `return -1` sentinels, never
  `std::exit`.
- `fp::unwrap` / `fp::expect` are allowed only in tests and `main.cpp`.
- Messages are lowercase, no trailing period, and include the sizes involved:
  `"matmul: inner dimensions 3 and 4 do not match"`.
- Float comparison uses `fp::approx_equal` (scale-aware) or an explicit
  tolerance; never `==` in tests.
- Where fp already returns `Result` (`fp::solve`, `fp::from_text`,
  `fp::from_bytes`, `fp::read_*`), propagate it — do not unwrap at the boundary
  unless the caller's contract is "cannot fail".

```cpp
inline fp::Result<Matrix> matmul(Matrix const &a, Matrix const &b) {
  if (a.cols() != b.rows())
    return fp::fail("matmul: inner dimensions " + std::to_string(a.cols()) +
                    " and " + std::to_string(b.rows()) + " do not match");
  ...
}
```

## ForgeFP usage rules

| Need | Use | Do not |
|---|---|---|
| Fallible chain | `>>=`, `fp::and_then`, `fp::map` | nested `if (!r.is_ok())` |
| Collect several errors | `fp::Validation`, `fp::validate_all` | manual error vectors |
| Iterate / transform a range | `fp::map`, `fp::filter`, `fp::fold_left`, `fp::zip_with` | hand-rolled index loops in non-hot code |
| Mutate in place (hot) | `fp::for_each`, `fp::transform_inplace`, `fp::map_to`, `fp::zip_transform_inplace` | eager combinators in a loop |
| Accumulate numbers | `fp::sum`, `fp::fold_left`, `fp::dot`, `fp::reduce` | `std::accumulate` in hot paths |
| Matrix math | `fp::matmul`, `fp::matvec`, `fp::solve`, `fp::transpose`, `fp::row_sums`, … | per-model triple loops |
| Stable probability math | `fp::softmax`, `fp::softmax_rows`, `fp::log_softmax`, `fp::logsumexp`, `fp::sigmoid` | `exp(x)/sum(exp(x))` |
| Randomness | `fp::Rng` passed explicitly | `std::random_device`, statics |
| Raw memory / scratch | `fp::Buffer`, `fp::with_buffer`, `fp::Arena` | `new`/`delete`, `malloc` |
| Scoped cleanup | `fp::defer`, `fp::scope_exit` | duplicated cleanup on every return |
| 2D loops | `fp::for_each_index`, `fp::map2d`, `fp::map2d_indexed` | nested `for (i) for (j)` outside kernels |
| Lazy pipelines | `fp::views::map/filter/chunk/slide/zip_with` | materializing every intermediate |
| Strings / formatting | `fp::str::join`, `split`, `parse_numbers`, `to_string` | `std::stringstream` boilerplate |
| Files / bytes | `fp::read_lines`, `fp::read_bytes`, `fp::write_bytes`, `fp::ensure_directory` | `fstream` flag juggling |
| Serialization | `fp::to_text`/`from_text`, `fp::to_bytes`/`from_bytes` | per-type loops |
| Timing | `fp::now_seconds`, `fp::Stopwatch` | `std::chrono` at every call site |
| Parallelism | `fp::ThreadPool` + `par_map`/`par_for`/`par_map_to` | raw `std::thread` per task |
| Gradient checks | `fp::central_difference`, `fp::ad::derivative` | hand-written difference code |
| Anonymous recursion | `fp::fix` (trees, topological sorts) | `std::function` self-capture |

Rules:

- **Never reimplement an fp function.** If something is missing, add the
  general primitive to fp (documented in `fp/EXTENSIONS.md`) and call it.
- **Every module doc lists its "ForgeFP usage"**; the code must match that list.
- Hot loops stay plain loops *only* when fp has no zero-cost equivalent.
  `fp::inplace`, `fp::simd`, and `fp::linalg` exist precisely so that this is
  rare; when a raw loop is kept, it is documented in one line with the reason.
- Prefer `fp::Buffer` for reusable scratch (batch buffers, gradient buffers) so
  training loops stop allocating; `std::vector` is fine for owned results.
- `fp::simd` is opt-in: use it for large contiguous reductions and math
  (`dot`, `axpy`, `map_inplace`), not for tiny vectors.

## Naming

| Thing | Style | Example |
|---|---|---|
| Files | `snake_case.hpp` | `linear_regression.hpp` |
| Types | `PascalCase` | `Matrix`, `StandardScaler`, `DataLoader` |
| Functions | `snake_case` | `matmul`, `train_test_split` |
| Member functions | `snake_case` | `predict_proba`, `zero_grad` |
| Constants | `kPascalCase` or `inline constexpr` | `inline constexpr double kEps = 1e-12` |
| Private helpers | in `forgeml::detail` | `detail::gini_impurity` |
| Test files | `<module>_test.cpp` | `linalg_test.cpp` |

Avoid `get_` prefixes (`rows()` not `get_rows()`), avoid `_` suffixes unless a
name collides with a keyword (`lambda_`, `type_`).

## Types and numeric rules

- Default scalar is `double`; containers are `template <class T = double>`.
- **Precision policy**: kernels are templated on `forgeml::Scalar`
  (`src/core/scalar.hpp`); a `FORGEML_SINGLE_PRECISION` build uses `float` for
  PyTorch-class throughput, while tests and references stay `double`
  ([performance.md](performance.md#precision-policy)). Reductions accumulate in
  `double` even in a float build.
- `Vector<T>` is a contiguous 1-D container that is a range; `Matrix<T>` is a
  **grid** (`std::vector<Vector<T>>`, row-major) so every `fp::linalg` and
  `fp::grid` function applies directly. `Tensor<T>` uses `fp::Buffer<T>` for
  flat N-d storage.
- Models store `double` parameters in `Vector`/`Matrix`; optimizers update them
  in place via `fp::inplace`/`fp::simd`.
- All math must be finite-safe: use `fp::softmax`/`fp::log_softmax` (max
  subtraction), clip probabilities, and guard `fp::is_finite` on losses.
- `variance`/`stddev` take an explicit `ddof` (delta degrees of freedom):
  `variance(v, /*ddof=*/0)` is population variance, `1` is sample variance.
  Scalers and Naive Bayes use `ddof = 0`; covariance uses `ddof = 1`.
- Per-column variance/stddev are the one statistics gap fp does not fill yet;
  `math/stats.hpp` provides `col_variances`/`col_stddevs` built on fp
  primitives (candidate for a future fp extension).

## Randomness

- One type: `fp::Rng` (from `fp/random.hpp`).
- Every function that randomizes takes `fp::Rng &` explicitly:
  `train_test_split(data, 0.2, rng)`.
- Library code never constructs an `fp::Rng`; `main` and tests seed explicitly
  (`fp::Rng rng(1234)`), so every run is reproducible.
- Convenience overloads without an `fp::Rng` are not provided.
- Sampling without replacement and weighted choice come from `fp::Rng`
  (`sample_indices`, `categorical`); do not hand-roll them.

## Determinism

What is promised, per path — the contract tests rely on:

| Path | Promise |
|---|---|
| CPU, `double`, seeded `fp::Rng` | **bit-reproducible** (same seed → same bits) |
| CPU, float32 build | bit-reproducible for elementwise kernels; reductions may differ from the double build by the tolerance |
| `fp::par_for` reductions | **not** bit-reproducible (the split order varies); tests compare with `fp::approx_equal` |
| GPU kernels | elementwise bit-identical to the CPU; `matmul`/reductions/softmax within the documented tolerance ([gpu.md](gpu.md#opt-in-mechanics)) |
| RL tier | seeded runs, reported as means with confidence intervals; never a single run ([rl.md](rl.md#the-tier-contract)) |
| Benchmarks | real time, shapes in the label, machine state recorded ([performance.md](performance.md#measurement)) |

The rules that follow: a test that needs bit equality uses the single-threaded
CPU path; a test that accepts tolerance says so in its name or assertion; no
module may claim determinism it does not have.

## Performance rules

- Row-major grids; `Matrix` rows are `Vector`s, so `fp::matmul`'s `i-k-j`
  order and cache behavior apply unchanged.
- `reserve()` when the final size is known; reuse `fp::Buffer` scratch across
  batches instead of allocating per step.
- Optimizer updates use `fp::axpy_inplace` / `fp::
  zip_transform_inplace`; parameter updates never allocate.
- Large independent work (row-wise transforms, tiled kernels) uses
  `fp::par_for` / `fp::par_map_to` with a reused `fp::ThreadPool`.
- Every model exposes its `parameters()` as references so optimizers update in
  place.
- A raw loop is acceptable only in a numeric kernel that fp does not provide;
  it gets a one-line comment saying why.
- **Budgets are gates**: every hot stage has a benchmark with a shape and a
  budget, a training step allocates nothing after warm-up (`perf/alloc_counter`),
  and a >5% regression fails `forge bench --compare` — see
  [performance.md](performance.md#budgets-and-gates).

## Logging and output

- Library code never writes to `std::cout` / `std::cerr`.
- Training progress goes through `utils/logging.hpp` (`Logger`) or a callback
  (`std::function<void(EpochStats const&)>`); `EpochStats` carries
  `fp::Stopwatch`-measured seconds.
- Formatting uses `fp::str::to_string` / `fp::str::join`, not raw streams.
- `operator<<` for containers is for debugging and tests only.

## Tests

- One test file per module: `test/<module>_test.cpp`, GoogleTest.
- Every formula gets at least one hand-computed case.
- Every error branch gets a test (`EXPECT_FALSE(r.is_ok())`).
- Every layer/loss with a backward pass gets a gradient check against
  `utils/gradient_check.hpp`, which itself uses `fp::central_difference` and
  `fp::ad::derivative`.
- Property tests where cheap:
  - `transpose(transpose(A)) == A`
  - `matmul(A, I) == A`
  - `scaler.inverse_transform(scaler.transform(X)) ≈ X`
  - k-fold test folds partition the dataset exactly once
  - `softmax` rows sum to 1 and are finite for large inputs
- Deterministic: `fp::Rng` seeds are literals, expected values are literals.
- Tests must not depend on execution order or wall-clock time.

## Formatting

- 2-space indent, 80-column soft limit, braces on the same line.
- Include order: own header, ForgeFP, stdlib, then project headers.
- No `using namespace` in headers; `using` declarations only inside `.cpp` /
  tests.
- Comments explain *why*, not *what*; formulas go in the header block of the
  function that implements them.

## Definition of done (repeat)

A file is done when: it compiles clean, matches its module doc, lists and uses
its ForgeFP functions, returns `Result` for all expected failures, has passing
tests, has no hidden state, and its documented formulas match the code.
